### Implement consistent naming conventions
Consistent naming conventions for folders, files and projects help you stay organised and make it easier to locate files and to reference files if someone from a different TF needs to get something from your folders. You can create a naming convention cheat sheet or include your naming conventions in the README.
Example of naming conventions:

1. standard LocationID (e.g. in Johnny Decimal System). Only meaningful within the folder structure, can help to be on top of your hierarchy.
2. date first --> can be relevant for documents that are routinely produced e.g. minutes, ppt presentations, etc.
3. version control --> you can include a version log within your documents and/or in your naming of the document. For example, by using words such as "draft", "version_x.y" or "v_x.y", and "final", you can embed version control in your naming convention.
It is a good idea to also have a descriptive but short name in the file names. 

e.g. what does this file name tell us? 
"11.03 TF_folder_recommendations_v1.4" 
location: the file is located in 11.03
topic: the file is about "folder recommendations"
version control: this is the version 1.4 (probably has been revised before, previous versions may be found in the archive, if not deleted).


Naturally, not all files may need a date, or a version embedded in their name. The take-away is that it is good to actively think and decide on your naming conventions.
